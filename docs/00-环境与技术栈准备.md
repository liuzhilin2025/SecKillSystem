## 二、Docker 中间件（按阶段逐步启动）

```yaml
# docker-compose.yml（示例骨架，端口按需调整）
services:
  mysql:
    image: mysql:8.0
    ports: ["3306:3306"]
    environment:
      MYSQL_ROOT_PASSWORD: root123456
      TZ: Asia/Shanghai
    command: --default-authentication-plugin=mysql_native_password
             --character-set-server=utf8mb4
    volumes:
      - ./data/mysql:/var/lib/mysql

  redis:
    image: redis:7.2
    ports: ["6379:6379"]
    command: redis-server --appendonly yes --requirepass 123456
    volumes:
      - ./data/redis:/data

  rabbitmq:
    image: rabbitmq:3.13-management
    ports: ["5672:5672", "15672:15672"]
    environment:
      RABBITMQ_DEFAULT_USER: admin
      RABBITMQ_DEFAULT_PASS: admin123

  nacos:
    image: nacos/nacos-server:v2.3.2
    ports: ["8848:8848", "9848:9848"]
    environment:
      MODE: standalone
```

> 使用方式：`docker compose up -d mysql redis`，用到哪个起哪个，不用全开。

## 三、JMeter 快速上手

必须掌握的最小技能集：

| 元件 | 作用 |
|---|---|
| 线程组（Thread Group） | 并发用户数、Ramp-up、循环次数 |
| HTTP 请求 | 接口地址、方法、Header、Body |
| HTTP 信息头管理器 | `Content-Type: application/json`、Token |
| 聚合报告 | QPS(Throughput)、平均/中位/P95/P99、错误率 |
| JSON 提取器 | 从登录响应提取 Token 供后续接口使用 |
| CSV 数据文件设置 | 多用户参数化，模拟不同用户抢购 |

### 压测原则

1. **先单接口后链路**：先压商品列表，再压下单全链路。
2. **关注 P99 而非平均值**：平均值会掩盖长尾。
3. **压测前清数据、预热**：避免首轮 JIT/连接池初始化影响结果。
4. **逐步加压找拐点**：50 → 100 → 500 → 1000 线程，观察 QPS 是否出现拐点与错误率上升。

## 验收标准

能够在 30 分钟内从零拉起 MySQL + Redis，并用 JMeter 对一个 `/ping` 接口跑出 1000 并发、QPS > 3000 的结果。

## 常见坑

- Windows 上 Docker 未开 WSL2 导致启动失败
- MySQL 8 默认 `caching_sha2_password` 与旧版驱动不兼容
- JMeter 未设置线程数与 Ramp-up 关系，导致"假并发"（比如 1000 线程 100 秒 Ramp-up 其实只有 10 QPS）
- 忘记关闭 JMeter 的"查看结果树"监听器，压测机自身先成瓶颈
