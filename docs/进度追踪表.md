## 三、问题排查记录

| 日期 | 现象 | 根因 | 解决方案 | 是否已解决 |
|---|---|---|---|---|
| 2026-10-15 | 下单接口 100% 报错 `ERR user_script:61: Script attempted to access nonexistent global variable 'remainStock'` | Lua 里 `DECR` 的返回值没有赋值，第 61 行却直接读 `remainStock`；Redis 沙箱对未定义全局变量直接抛错（不是返回 nil） | 改为 `local remainStock = redis.call('DECR', KEYS[1])`，判断处直接用 `remainStock <= 0` | ✅ |
| 2026-10-15 | 库存还有 20，下单却提示"商品已售罄" | 上一轮压测把库存抢到 0 时写了 `seckill:soldout:1:6`，TTL 到活动结束（77 天）；重新预热只 `SET` 了库存，没删售罄标记 | 预热逻辑中同步 `DEL` 售罄标记；脏标记需手动清理或重新预热 | ✅ |
| 2026-10-16 | 下单接口报 `UndeclaredThrowableException` → `getInputStream() has already been called for this request` | `@ApiOperationLog` 无差别序列化所有入参，`HttpServletRequest` 被 Jackson 当 Bean 反射调用 `getReader()`，而 `@RequestBody` 已消费了 body | 切面过滤 `ServletRequest`/`ServletResponse`，并对序列化失败加 try-catch 兜底 | ✅ |
| 2026-10-19 | `@Recover` 兜底方法没有被调用 | 第一个参数写成 `Exception`，与 `@Retryable(retryFor = AmqpException.class)` 不匹配；同类自调用会绕过 AOP 代理 | 参数类型改为 `AmqpException`，确保跨 bean 调用 | ✅ |
| 2026-10-19 | 以为补偿状态已更新，实际数据库没变 | 在 `updateStatusByOrderNo(...)` 后又调了 `existCompensation.setStatus(...)`，只改内存 POJO | 删除无效的 `setStatus`，以 mapper 更新为准 | ✅ |
| 2026-10-20 | 压测时大量请求返回"请求过于频繁" | IP 维度限流 50 次/10s，JMeter 1000 并发全部来自同一 IP | 压测前临时调大 `ipMaxCount` 或摘掉 `@SeckillRateLimit` | 待验证 |
